# 文档质量检查规范 (Quality Checklist)

## 4.1 三级检查体系

### 一级：完整性检查 (Completeness)
- [ ] 标题是否包含核心关键词（稻盛和夫、软件工程、成长）？
- [ ] 摘要能否独立成篇？（不看正文是否完整）
- [ ] 每个提纲节点都有对应内容？（无悬空标题）
- [ ] 结论是否回应了摘要中提出的问题？
- [ ] 稻盛和夫观点是否都有原文或页码引用？

### 二级：一致性检查 (Consistency)
- [ ] 术语全文统一（如前文用"持续努力"，后文不能用"坚持不懈"指同一概念）
- [ ] 数据前后一致（如前文说"3个场景"，后文枚举是否为3个）
- [ ] 时态统一（回忆过去用过去时，现状反思用现在时，规划用将来时）
- [ ] 人称统一（禁止"我/我们/笔者"混用，以"我"为主）
- [ ] 标点规范（中文正文用全角标点，英文术语保留半角括号）

### 三级：有效性检查 (Effectiveness)
- [ ] 每章删除测试：删除该章是否损害整体理解？如否，则该章冗余
- [ ] 反向阅读测试：从结论倒推，论据是否足够支撑？
- [ ] 陌生人测试：假设读者是领域外人士，是否有概念未解释？
- [ ] 时间胶囊测试：三年后重读，是否仍能理解核心观点？
- [ ] 行动导向测试：读者读完后能采取什么具体行动？（纯信息类文档除外）

## 4.2 题材特化检查项

| 题材 | 特化检查项 |
|-----|----------|
| 软件工程报告 | 可复现性：关键配置/版本号/环境参数是否完整？安全性：是否泄露密钥/内网IP？ |
| 读书心得 | 原文引用占比：是否过度引用沦为摘抄？个人思考占比：感想是否依附于具体文本？ |
| 入党申请书 | 政治表述准确性：党的性质/宗旨/指导思想引用是否精准？真实性：事例是否可查证？ |

## 4.3 评分与迭代机制
- **基线分**：满分100，一级检查每项15分，二级每项10分，三级每项5分
- **通过标准**：≥85分可输出；70-85分需标注待改进项；<70分重写
- **迭代指令**：若未通过，使用"基于[具体检查项]的反馈，请修正[具体位置]，要求[具体标准]"

## 4.4 常见失败模式 (Anti-patterns)
| 模式名称 | 症状 | 修复策略 |
|---------|------|---------|
| 头重脚轻 | 背景写3页，结论2句话 | 强制结论区字数≥摘要区×2 |
| 概念通货膨胀 | 堆砌术语无实质内容 | 每个术语必须跟"也就是说..."的解释句 |
| 情感透支 | 形容词密度>20% | 将所有"非常/极其/深刻"替换为具体程度副词或数据 |
| 正确的废话 | "我们要努力学习" | 加入主语、时间、衡量标准："我计划每天阅读30分钟" |
| 逻辑跳跃 | "因为A，所以C"缺B | 强制补充中间环节，或使用"这意味着..."过渡 |

## 4.5 本次读书心得的特化检查项

### 身份真实性检查
- [ ] 是否始终保持"大二软件工程学生"的身份视角？
- [ ] 是否出现了"我们程序员"这种泛化表述？（应改为"我作为软件工程学生"）
- [ ] 是否出现了"工作多年"、"带团队"等不符合大二学生身份的表述？
- [ ] 场景描述是否具体？（如不说"我参加过很多项目"，而说"大二上学期，我参加了一个Java Web项目"）

### 技术场景真实性检查
- [ ] 技术术语使用是否准确？（如"Git冲突"、"Spring Boot"、"MySQL"）
- [ ] 场景描述是否符合大二学生的实际水平？（如不说"我主导了一个大型分布式系统"，而说"我参与了课程项目的开发"）
- [ ] 挫败感描述是否真实？（如允许说"调试了3天还是报错"、"期末考试数据结构差点挂科"）

### 稻盛和夫思想应用检查
- [ ] 每次引用稻盛和夫观点后，是否紧接了"这对我的具体启示是..."？
- [ ] 是否避免了说教（如"我们应该..."）？
- [ ] 是否避免了拔高（如"稻盛和夫的思想改变了我的人生"）？
- [ ] 是否避免了泛化（如"人生态度决定一切"）？
- [ ] 原文引用占比是否控制在30%以内？（避免沦为摘抄）

### 内容深度检查
- [ ] 是否有具体的行动转化？（如"接下来一个月，我计划每天写代码1小时"）
- [ ] 是否有批判性思考？（同意什么/质疑什么/补充什么）
- [ ] 是否有局限声明？（如"本文仅基于个人经历，可能不适用于所有人"）

### 语言风格检查
- [ ] 是否使用了网络流行语？（如"绝绝子"、"yyds"、"卷不动了"）
- [ ] 是否使用了套路化总结语？（如"综上所述"、"总而言之"）
- [ ] 是否有空洞修饰？（如"非常有意义"、"深受启发"而无具体支撑）
- [ ] 是否有过度谦虚或过度自信？
- [ ] 是否保持了真诚反思的语气？

### 结构完整性检查
- [ ] 导语是否包含了背景、核心发现、结构预告三要素？
- [ ] 每章是否遵循"场景-观点-反思"的三段式结构？
- [ ] 章节之间是否有过渡？
- [ ] 结论是否回应了导语中提出的问题？
- [ ] 字数是否达到3000字以上？

## 4.6 自检清单（生成过程中使用）

### 每完成一个章节后自检
- [ ] 本节内容是否直接支撑主命题？
- [ ] 本节是否在讲道理而非结合真实经历？
- [ ] 本节是否引入了与"大二软件工程学生"身份无关的内容？
- [ ] 本节是否有具体的场景描述？
- [ ] 本节是否有稻盛和夫观点的引用？
- [ ] 本节是否有个人反思？
- [ ] 本节字数是否符合分配？

### 全文完成后自检
- [ ] 总字数是否达到3000字以上？
- [ ] 是否有6个以上的具体场景？
- [ ] 是否有稻盛和夫的6个以上核心观点？
- [ ] 是否有具体的行动转化计划？
- [ ] 是否有批判性思考和局限声明？
- [ ] 是否保持了"大二软件工程学生"的身份视角？
- [ ] 是否避免了说教、拔高、泛化？
- [ ] 是否避免了网络流行语和套路化表达？
- [ ] 是否有真诚反思的语气？

## 4.8 通过标准
- **优秀**：≥270分（90%以上）
- **良好**：240-269分（80-89%）
- **合格**：210-239分（70-79%）
- **不合格**：<210分（70%以下）

## 4.9 迭代指令示例
- "基于身份真实性检查的反馈，请修正第五章，要求：删除'我们程序员'这种泛化表述，改为'我作为软件工程学生'，并补充具体的团队协作场景。"
- "基于稻盛和夫思想应用检查的反馈，请修正第三章，要求：每次引用稻盛和夫观点后，必须紧接'这对我的具体启示是...'，避免说教。"
- "基于内容深度检查的反馈，请修正结论部分，要求：补充具体的行动转化计划，如'接下来一个月，我计划每天写代码1小时、每周复盘一次'。"
