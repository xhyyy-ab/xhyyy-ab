## 1. 项目概述 (Overview)

### 1.1 产品定义
一款面向普通用户的**皮肤病智能自查与科普工具**微信小程序。用户通过拍照上传皮肤患处照片，AI 提供常见皮肤病的初步识别参考与科普知识，帮助用户了解症状、缓解焦虑、科学就医。

### 1.2 核心原则
- **辅助参考，绝不替代医生**：所有识别结果仅为 AI 算法推测，不构成医疗诊断
- **隐私优先**：用户生物特征数据（皮肤照片）严格加密存储与传输
- **合规底线**：严格遵守《个人信息保护法》《数据安全法》及互联网医疗相关规定

### 1.3 目标用户
| 属性 | 描述 |
|------|------|
| 年龄 | 18-55 岁 |
| 身份 | 非医学背景普通互联网用户 |
| 场景 | 皮肤出现异常症状（红斑/瘙痒/脱屑/水疱等），希望先初步了解 |
| 痛点 | 不知病因、不确定是否严重、不知道该挂什么科、心理恐慌 |
| 频次 | 偶发性需求，中低频使用 |

### 1.4 成功指标 (KPI)
| 指标 | MVP 目标值 |
|------|-----------|
| 识别请求成功率 | ≥ 95% |
| 识别结果页完读率 | ≥ 80% |
| 免责声明确认率 | 100%（强制） |
| 用户留存（7日） | ≥ 20% |
| 科普文章平均阅读时长 | ≥ 45 秒 |

```
[拍照页] --提交照片--> [分析中页] --API返回--> [结果页]
                                      |
                                      └--超时/失败--> [错误页：重新尝试]
```

## 4. 数据规格 (Data Specification)

### 4.1 核心数据模型

```
User（用户）
├── unionId: String (PK)
├── openId: String
├── nickName: String
├── avatarUrl: String
├── createdAt: Timestamp
└── lastLoginAt: Timestamp

DiagnosisRecord（识别记录）
├── id: String (PK)
├── userId: String (FK -> User.unionId)
├── images: Array<String> (照片URL列表)
├── result: Object
│   ├── primary: { diseaseName, confidence, description }
│   ├── alternatives: Array<{ diseaseName, confidence }> (最多2个)
│   └── urgencyLevel: Enum [low, medium, high]
├── disclaimerAcknowledged: Boolean (必须 true)
├── createdAt: Timestamp
└── status: Enum [pending, completed, failed]

Article（科普文章）
├── id: String (PK)
├── title: String
├── summary: String
├── coverImage: String
├── content: String (富文本 HTML/Markdown)
├── category: Enum [by_location, by_type, seasonal]
├── tags: Array<String>
├── views: Number
├── author: String
├── reviewStatus: Enum [draft, reviewed, published]
├── createdAt: Timestamp
└── updatedAt: Timestamp

Favorite（收藏）
├── id: String (PK)
├── userId: String (FK)
├── articleId: String (FK)
└── createdAt: Timestamp
```

### 4.2 API 接口规格

#### 4.2.1 认证接口

```
POST /api/v1/auth/login
Request:
{
  "code": String,        // wx.login 返回的 code
  "userInfo": Object     // 微信授权用户信息（可选）
}

Response:
{
  "code": 0,
  "data": {
    "token": String,     // JWT Token
    "expiresIn": 7200,   // 秒
    "user": {
      "unionId": String,
      "nickName": String,
      "avatarUrl": String
    }
  }
}
```

#### 4.2.2 识别接口

```
POST /api/v1/diagnosis/analyze
Headers: Authorization: Bearer <token>
Content-Type: multipart/form-data

Request:
{
  "images": File[],      // 1-3 张图片，单张 ≤ 5MB，格式 jpg/png
  "bodyPart": Enum       // [face, trunk, limb, hand_foot, other]（可选）
}

Response:
{
  "code": 0,
  "data": {
    "recordId": String,
    "status": "completed",
    "result": {
      "primary": {
        "diseaseId": String,
        "diseaseName": String,
        "confidence": Number,      // 0-1
        "description": String,      // 一句话说明
        "suggestedDepartment": String  // 建议就诊科室
      },
      "alternatives": [
        {
          "diseaseId": String,
          "diseaseName": String,
          "confidence": Number
        }
      ],
      "urgencyLevel": "low" | "medium" | "high",
      "disclaimer": String          // 免责声明全文
    },
    "relatedArticles": [
      { "id": String, "title": String, "coverImage": String }
    ]
  }
}

Error Cases:
- code: 1001 "照片不清晰，请重新拍摄"
- code: 1002 "无法识别，建议就医检查"
- code: 1003 "服务繁忙，请稍后重试"
```

#### 4.2.3 文章接口

```
GET /api/v1/articles
Query:
  ?category=by_location|by_type|seasonal
  &tag=String
  &page=1
  &pageSize=10

Response:
{
  "code": 0,
  "data": {
    "list": [Article],
    "total": Number,
    "hasMore": Boolean
  }
}

GET /api/v1/articles/:id
Response: { "code": 0, "data": Article }
```

#### 4.2.4 用户相关接口

```
GET /api/v1/user/history?page=1&pageSize=20
Response: { "code": 0, "data": { "list": [DiagnosisRecord], "total": Number } }

POST /api/v1/user/favorites
Request: { "articleId": String }

GET /api/v1/user/favorites
Response: { "code": 0, "data": { "list": [Article] } }
```

### 6.3 AI 识别方案

**MVP 推荐方案：第三方 SaaS API**

| 方案 | 优点 | 缺点 | 适用阶段 |
|------|------|------|---------|
| 第三方 API | 快速上线、无需训练、按需付费 | 成本较高、定制化受限 | MVP |
| 自研模型 | 成本低（长期）、可深度定制 | 需标注数据、训练周期长、准确率爬坡 | 成长期 |

**建议接入流程：**
1. 调研并申请第三方皮肤病 AI 识别 API（如腾讯医典、微医、或专业医学影像 AI 公司）
2. 封装适配层，统一输入输出格式
3. 建立 Fallback 机制：API 超时/失败时返回友好提示
4. 记录所有识别日志，用于后续模型优化数据积累

## 9. 风险与应对 (Risk Management)

| 风险 | 概率 | 影响 | 应对措施 |
|------|------|------|---------|
| AI 识别准确率不达预期 | 中 | 高 | 设置合理预期（参考级）；低置信度 Fallback；持续收集数据优化 |
| 医疗合规问题 | 低 | 极高 | 严格免责声明；不诊断不开方；法务审核文案；定期合规自查 |
| 用户隐私投诉 | 中 | 高 | 透明隐私政策；最小化数据收集；加密存储；提供删除入口 |
| 第三方 AI 服务不稳定 | 中 | 高 | 封装适配层，便于切换服务商；降级策略；SLA 合同约束 |
| 科普内容医学准确性 | 中 | 高 | 所有文章需医学专业人士审核；标注审核人；定期更新 |
| 小程序审核被拒 | 低 | 中 | 提前阅读《微信小程序运营规范》；医疗类小程序特殊资质准备 |
