## 1. 引言

### 1.1 编写目的

本文档为 **SkinCheck 皮肤病智能自查小程序** 的软件开发提供完整、明确、可验证的需求定义。本文档面向以下读者：
- 产品经理（需求确认与变更管理）
- UI/UX 设计师（界面设计依据）
- 前端/后端工程师（功能开发依据）
- 测试工程师（测试用例设计依据）
- 项目管理者（进度跟踪与验收依据）

### 1.2 项目背景

皮肤病是人群中最常见的健康问题之一。据统计，超过 90% 的人一生中至少患过一种皮肤病。大量用户在面对皮肤异常时存在以下痛点：
- 不确定症状严重程度，产生不必要的恐慌
- 不知道该挂什么科室，就医流程低效
- 缺乏权威、易懂的皮肤病科普知识
- 不方便或不愿意立即去医院，希望先初步了解

SkinCheck 旨在通过 AI 图像识别技术 + 权威医学科普内容，为用户提供便捷的皮肤病自查参考工具，帮助用户科学认知症状、合理就医。

### 1.3 术语定义

| 术语 | 英文 | 定义 |
|------|------|------|
| AI 识别 | AI Diagnosis | 基于深度学习模型的皮肤病图像分类与预测 |
| 置信度 | Confidence Score | AI 模型对识别结果的确定性度量，取值范围 0-1（0%-100%） |
| 免责声明 | Medical Disclaimer | 明确告知用户识别结果仅供参考、不构成医疗诊断的法律声明 |
| MVP | Minimum Viable Product | 最小可行产品，具备核心功能可上线验证的版本 |
| 科普文章 | Educational Content | 经医学审核的皮肤病知识图文内容 |
| 识别记录 | Diagnosis Record | 用户单次拍照识别的完整数据记录 |
| 关联推荐 | Related Recommendation | 基于识别结果自动匹配的科普文章 |

### 2.2 用户角色

| 角色 | 标识 | 描述 | 权限 |
|------|------|------|------|
| 普通用户 | USER | 使用小程序进行皮肤病自查和阅读科普的微信用户 | 拍照识别、浏览文章、查看历史、收藏 |
| 系统管理员 | ADMIN | 后台内容管理人员 | 文章发布/编辑/审核、Banner 配置、数据查看 |
| 医学专家 | EXPERT | 科普内容审核人员 | 文章医学审核、内容准确性校验 |

### 2.3 运行环境

| 组件 | 环境要求 |
|------|---------|
| 客户端 | 微信客户端 8.0.0 及以上版本，iOS 11+/Android 8+ |
| 服务端 | Node.js 18+ LTS，Linux 服务器 |
| 数据库 | MongoDB 6.0+，Redis 7.0+ |
| 网络 | 支持 4G/5G/Wi-Fi，弱网环境需有降级提示 |

### 2.4 约束与假设

**约束条件：**
- 必须遵守微信小程序平台审核规范，医疗类内容需特别注意合规
- AI 识别结果仅作参考，不得出现"诊断""确诊"等医疗术语
- 用户皮肤照片属于敏感个人信息，必须加密存储
- 免责声明必须在每次识别结果页强制展示

**假设条件：**
- 用户具备基础智能手机操作能力
- 用户能够拍摄清晰度满足 AI 识别要求的照片
- 第三方 AI 识别服务在 MVP 阶段可用且 SLA 满足要求
- 科普文章内容可由医学合作方或公开权威来源提供

### 3.2 用户认证模块 (FR-AUTH)

#### FR-AUTH-001 微信一键登录

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-AUTH-001 |
| **需求名称** | 微信一键登录 |
| **优先级** | P0 |
| **描述** | 用户通过微信授权快速完成登录，无需注册流程 |
| **前置条件** | 用户已安装微信客户端并授权小程序 |
| **触发条件** | 用户点击"开始自查"或进入个人中心时检测到未登录 |
| **基本流程** | 1. 用户触发登录流程  <br>2. 小程序调用 `wx.login()` 获取临时 code  <br>3. 后端用 code 换取微信 OpenID/UnionID  <br>4. 后端查询或创建用户记录  <br>5. 后端返回 JWT Token  <br>6. 小程序存储 Token，登录完成 |
| **异常流程** | E1: 用户拒绝授权 → 提示"登录后可使用识别功能"，保留"重新授权"按钮 <br> E2: 网络异常 → 提示"网络连接失败，请检查网络后重试" |
| **后置条件** | 用户处于登录态，可正常使用识别功能 |
| **业务规则** | BR-001: 首次登录需展示隐私政策，用户勾选同意后方可继续 |

### 3.3 AI 识别模块 (FR-DIAG)

#### FR-DIAG-001 拍照/选图上传

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-001 |
| **需求名称** | 拍照/选图上传 |
| **优先级** | P0 |
| **描述** | 用户通过相机拍摄或相册选择患处照片上传 |
| **前置条件** | 用户已登录 |
| **输入** | 照片 1-3 张，单张 ≤ 5MB，格式 JPG/PNG |
| **基本流程** | 1. 进入拍照页，显示拍摄引导浮层 <br> 2. 用户选择"拍照"或"从相册选择" <br> 3. 选择照片后显示缩略图预览 <br> 4. 用户可删除重选或添加更多照片（最多3张） <br> 5. 点击"开始分析"进入分析中页 |
| **拍摄引导内容** | "请确保：① 光线充足 ② 对焦清晰 ③ 包含周围正常皮肤 ④ 多角度拍摄更佳" |
| **业务规则** | BR-005: 必须至少上传 1 张照片才能提交 <br> BR-006: 照片选择后本地预览，上传时机为用户点击"开始分析"后 |

#### FR-DIAG-002 照片质量校验

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-002 |
| **需求名称** | 照片质量校验 |
| **优先级** | P1 |
| **描述** | 上传前对照片进行基础质量检测 |
| **校验项** | ① 分辨率 ≥ 640×480 <br> ② 非纯黑/纯白/模糊图像 <br> ③ 文件格式为 JPG/PNG <br> ④ 文件大小 ≤ 5MB |
| **校验结果** | 通过：进入上传流程 <br> 不通过：提示具体问题（如"照片过于模糊，请重新拍摄"） |

#### FR-DIAG-003 AI 识别请求

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-003 |
| **需求名称** | AI 识别请求 |
| **优先级** | P0 |
| **描述** | 将用户照片发送至 AI 识别服务进行分析 |
| **前置条件** | 照片已上传至对象存储，获取到图片 URL |
| **基本流程** | 1. 后端接收图片 URL 列表 <br> 2. 调用第三方 AI 识别 API <br> 3. 解析识别结果 <br> 4. 查询关联科普文章 <br> 5. 组装响应数据返回前端 <br> 6. 保存识别记录到数据库 |
| **性能要求** | 从提交到返回结果 ≤ 8 秒（含上传+识别+查询） |
| **业务规则** | BR-007: AI 识别超时时间为 5 秒，超时后返回友好错误提示 <br> BR-008: 识别失败时保存失败记录，便于后续排查 |

#### FR-DIAG-004 识别结果展示

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-004 |
| **需求名称** | 识别结果展示 |
| **优先级** | P0 |
| **描述** | 根据 AI 识别置信度分级展示结果 |
| **展示规则** | 见下表"置信度分级展示规则" |
| **结果元素** | ① 疾病名称 ② 置信度百分比 ③ 一句话说明 ④ 建议就诊科室 ⑤ 紧急程度标签 ⑥ 关联科普文章入口 |
| **紧急程度标签** | 🟢 可观察 / 🟡 建议近期就诊 / 🔴 建议尽快就医 |

**置信度分级展示规则：**

| 置信度范围 | 展示策略 | 结果数量 | 文案示例 |
|-----------|---------|---------|---------|
| ≥ 80% | 单结果展示，置信度高 | 1 | "较可能为：湿疹（87%）" |
| 50% - 80% | 多候选展示，置信度中等 | 2-3 | "可能为以下情况之一：① 湿疹（72%）② 接触性皮炎（58%）" |
| < 50% | 无法准确判断 | 0 | "无法准确判断，建议尽快就医检查" |

#### FR-DIAG-005 医疗免责声明

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-005 |
| **需求名称** | 医疗免责声明 |
| **优先级** | P0 |

#### FR-DIAG-006 识别失败处理

| 属性 | 内容 |
|------|------|
| **需求编号** | FR-DIAG-006 |
| **需求名称** | 识别失败处理 |
| **优先级** | P1 |
| **描述** | 处理 AI 识别过程中的各类异常情况 |
| **失败类型** | ① 网络超时 ② AI 服务异常 ③ 照片质量不满足识别要求 ④ 识别结果为空 |

| **业务规则** | BR-012: 失败时保存错误日志，包含错误类型、时间、用户 ID <br> BR-013: 连续失败 3 次后提示"如症状持续，请直接就医" |
