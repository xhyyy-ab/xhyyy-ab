# LLM对话历史管理实验报告

## 实验目的

本实验旨在实现LLM对话系统的历史管理功能，解决长对话上下文限制问题。具体目标包括：

1. 实现对话历史压缩机制，控制上下文长度
2. 开发关键信息提取功能，保存重要对话内容
3. 实现聊天历史搜索功能
4. 掌握对话摘要生成与信息检索技术

## 实验内容

### 1. 对话历史压缩机制

**压缩触发条件**：
- 对话轮数超过5轮
- 上下文总字符数超过3000字符

**压缩策略**：
- 保留最近30%的对话消息
- 对前70%的对话进行摘要压缩
- 生成结构化摘要，保留关键信息

**核心函数**：
- `calculate_context_length()`: 计算上下文总长度
- `count_conversation_rounds()`: 统计对话轮数
- `summarize_conversation()`: 生成对话摘要
- `check_and_summarize()`: 检查并执行压缩

### 2. 关键信息提取功能

**5W规则提取**：
- **Who（谁）**：涉及的主要人物或角色
- **What（做了什么）**：用户的主要需求和行动
- **When（什么时候）**：时间相关信息
- **Where（在何处）**：地点相关信息
- **Why（为什么）**：做某事的目的或原因

**提取流程**：
1. 每5轮对话自动触发提取
2. 调用LLM分析对话内容
3. 解析JSON格式的提取结果
4. 保存到本地日志文件 `D:\chat-log\log.txt`

### 3. 聊天历史搜索功能

**搜索触发方式**：
- 输入命令 `/search` + 查询内容
- 输入包含关键词的语句（如"查找聊天历史"）

**搜索实现**：
- 读取日志文件中的历史记录
- 构建搜索提示词，包含历史记录和当前问题
- 调用LLM进行语义搜索和回答生成
- 返回与查询相关的历史信息

### 4. 新增工具扩展

添加`search_chat_history`工具：
```json
{
  "name": "search_chat_history",

```

## 实验总结

### 技术要点

1. **上下文管理策略**：通过压缩和摘要平衡对话连贯性与API成本
2. **信息提取规范**：采用5W规则确保提取信息的完整性和结构化
3. **搜索机制设计**：结合LLM语义理解实现智能搜索
4. **持久化存储**：使用JSON格式保存，便于读取和解析

### 学习收获

通过本实验，掌握了以下核心技能：

- 对话历史管理的策略和实现方法
- LLM辅助的文本摘要生成技术
- 关键信息提取与结构化存储
- 基于语义的历史记录搜索
- 文件系统操作与持久化

### 改进方向

1. 增加对话历史的加密存储，提高安全性

4. 支持多关键词组合搜索
